## 第二章 功能模块设计

### 2.1 M01 — 桥梁基本信息管理模块

#### 2.1.1 模块功能描述

本模块完成桥梁基本信息的录入、修改、删除和多条件查询功能。桥梁信息是整个系统的核心数据，后续的基本状况卡片、初始检查和定期检查记录均以桥梁为单位进行关联。

**本模块实现的核心功能：**
- 新增桥梁信息（含30个字段的表单录入）
- 修改桥梁信息（保留原有编号，可修改其他字段）
- 删除桥梁信息（级联删除关联的卡片和检查记录）
- 按桥梁名称/编号关键词搜索
- 按所属路线筛选浏览
- 查看桥梁详细信息（含关联卡片和检查记录）

#### 2.1.2 模块输入数据

**用户输入数据（表单字段）：**

| 序号 | 字段名称 | 类型 | 是否必填 | 有效性校验规则 |
|------|---------|------|---------|-------------|
| 1 | bridge_id | 文本 | 是 | 最长20字符，格式如"BR001" |
| 2 | bridge_name | 文本 | 是 | 最长100字符，非空 |
| 3 | route_id | 下拉选择 | 否 | 必须在route表中存在 |
| 4 | unit_id | 下拉选择 | 否 | 必须在management_unit表中存在 |
| 5 | pile_no | 文本 | 否 | 最长50字符 |
| 6 | functional_type | 下拉选择 | 否 | 取值范围：highway/rail_highway |
| 7 | total_length | 数字 | 否 | 范围0.01-99999.99，保留2位小数 |
| 8 | deck_width | 数字 | 否 | 范围0.01-9999.99，保留2位小数 |
| 9 | design_load | 文本 | 否 | 最长50字符 |
| 10 | bridge_grade | 下拉选择 | 否 | 必须是dict_code中inspect_grade类别的编码 |
| 11 | built_date | 日期 | 否 | 合法日期格式YYYY-MM-DD |
| 12 | status | 单选 | 否 | 取值active或inactive，默认active |

**从物理模型获取的数据：**

| 数据用途 | 来源表 | 获取条件 |
|---------|--------|---------|
| 路线列表（下拉选项） | route | 查询所有记录，按route_id排序 |
| 管养单位列表（下拉选项） | management_unit | 查询所有记录 |
| 养护等级字典（下拉选项） | dict_code | WHERE dict_type='inspect_grade' AND is_active=1 |
| 桥梁列表（查询结果） | bridge JOIN route | 支持keyword模糊匹配、route_id精确筛选 |

#### 2.1.3 模块输出数据

| 输出内容 | 表现形式 | 数据来源 |
|---------|---------|---------|
| 桥梁列表 | HTML表格（分页），每个桥梁一行含编号/名称/路线/桩号/桥长/桥宽/等级/操作按钮 | bridge表 JOIN route表 |
| 桥梁详细信息 | HTML卡片布局，分基本信息/卡片信息/结构信息/关联检查记录四个区域 | bridge表 ← bridge_card表 ← bridge_structure等 |
| 操作结果提示 | Bootstrap Alert消息框（绿色成功/红色错误） | 操作返回值 |
| 新建/编辑表单 | HTML表单，含输入框/下拉选择/日期控件 | 同输入数据 |

#### 2.1.4 模块设计流程

```
开始
  │
  ├─[列表页] GET /bridge/
  │   ├─ 加载路线列表（下拉筛选）
  │   ├─ 获取搜索条件 keyword, route_id
  │   ├─ 执行数据库查询：
  │   │   SELECT * FROM bridge
  │   │   WHERE bridge_name LIKE '%keyword%' OR bridge_id LIKE '%keyword%'
  │   │   AND (route_id = ? OR '' = '')
  │   │   ORDER BY created_at DESC
  │   ├─ 渲染bridge_list.html模板
  │   └─ 输出HTML表格

  ├─[新增] GET /bridge/create
  │   ├─ 加载路线列表、单位列表、字典数据
  │   ├─ 渲染bridge_form.html模板（空表单）
  │   └─ 等待用户提交
  │
  ├─[新增提交] POST /bridge/create
  │   ├─ 校验required字段
  │   ├─ 校验字段格式（字符串长度/数值范围）
  │   ├─ INSERT INTO bridge (...)
  │   ├─ 提示"桥梁创建成功"
  │   └─ 重定向到桥梁列表
  │
  ├─[编辑] GET /bridge/<id>/edit
  │   ├─ 按bridge_id查询桥梁
  │   ├─ 404处理（桥梁不存在）
  │   ├─ 加载路线列表、单位列表、字典数据
  │   ├─ 渲染bridge_form.html模板（预填当前值）
  │   └─ 等待用户提交
  │
  ├─[编辑提交] POST /bridge/<id>/edit
  │   ├─ 校验字段
  │   ├─ UPDATE bridge SET ... WHERE bridge_id=?
  │   ├─ 提示"桥梁信息已更新"
  │   └─ 重定向到桥梁详情
  │
  ├─[详情] GET /bridge/<id>
  │   ├─ 按bridge_id查询桥梁
  │   ├─ 关联查询：bridge_card, bridge_structure, initial_inspection, regular_inspection
  │   ├─ 渲染bridge_detail.html模板
  │   └─ 输出详情页面（含基本信息+卡片信息+关联检查记录）
  │
  ├─[删除] POST /bridge/<id>/delete
  │   ├─ 级联删除（bridge_card → structure/archive/history/maintenance）
  │   ├─ DELETE FROM bridge WHERE bridge_id=?
  │   ├─ 提示"桥梁已删除"
  │   └─ 重定向到桥梁列表
  │
  └─[API] GET /bridge/api/list
      ├─ SELECT bridge_id, bridge_name FROM bridge WHERE status='active'
      └─ 返回JSON列表（供其他模块下拉引用）
```

### 2.2 M02 — 桥梁基本状况卡片管理模块

#### 2.2.1 模块功能描述

本模块基于《JTG 5120-2021》规范附录A，实现桥梁基本状况卡片的电子化管理。以"一桥一档"为原则，对每座桥梁建立完整的数字化档案，包含结构信息、档案资料、检测评定历史和养护处治记录四大子模块。

**本模块实现的核心功能：**
- 桥梁基本状况卡片查看（与桥梁详情页联动）
- 桥梁结构信息管理（按部位分类添加构件信息）
- 档案资料记录管理（9类档案的完整程度标记）
- 检测评定历史管理（记录历次检查评定）
- 养护处治记录管理（记录维修/加固/改造信息）

#### 2.2.2 模块输入数据

**结构信息子模块输入：**

| 字段 | 类型 | 校验规则 | 来源表 |
|------|------|---------|--------|
| part_category | 下拉选择 | NOT NULL，必须是dict_code中struct_part类别的编码 | dict_code |
| component_name | 下拉选择 | NOT NULL，按部位动态关联选项（如上部→主梁/主拱圈/桥塔） | 固定枚举 |
| struct_form | 文本 | 最长100字符 | — |
| material | 文本 | 最长100字符 | — |

**档案资料子模块输入：**

| 字段 | 类型 | 校验规则 | 来源表 |
|------|------|---------|--------|
| archive_type | 下拉选择 | NOT NULL，9种档案类型之一 | dict_code |
| completeness | 下拉选择 | 全/不全/无 | dict_code |
| archive_form | 下拉选择 | 纸质/电子文件 | — |

**检测评定历史子模块输入：**

| 字段 | 类型 | 校验规则 |
|------|------|---------|
| inspect_date | 日期 | NOT NULL，合法日期 |
| inspect_category | 文本 | 检测类别（初始检查/定期检查/特殊检查） |
| tech_evaluation | 文本 | 评定结果或结论 |
| treatment_measure | 文本 | 处治对策 |
| next_inspect_date | 日期 | 下次检测时间 |

**养护处治记录子模块输入：**

| 字段 | 类型 | 校验规则 |
|------|------|---------|
| period_desc | 文本 | 时间段描述 |
| category | 下拉选择 | 维修/加固/改造 |
| reason | 文本 | 处治原因 |
| cost | 数字 | 工程费用（万元） |
| fund_source | 文本 | 经费来源 |

#### 2.2.3 模块输出数据

| 输出内容 | 表现形式 | 数据来源 |
|---------|---------|---------|
| 桥梁基本状况卡片 | HTML页面内嵌卡片，分5个区域：行政识别/技术指标/结构信息/档案资料/检测历史 | bridge_card JOIN bridge_structure JOIN archive_record JOIN inspection_history JOIN maintenance_record |
| 结构信息表格 | HTML表格（部位/构件/形式/材料） | bridge_structure表 |

| 检测评定历史 | HTML表格（时间/类别/结论/处治对策/下次检测） | inspection_history表 |
| 养护处治记录 | HTML表格（时间/类别/原因/费用） | maintenance_record表 |

  │   └─ 刷新页面
  │
  ├─[添加检测历史] 类似流程 → INSERT INTO inspection_history
  │
  └─[添加养护记录] 类似流程 → INSERT INTO maintenance_record

### 2.3 M03 — 初始检查记录管理模块

#### 2.3.1 模块功能描述

本模块基于《JTG 5120-2021》附录B桥梁初始检查记录表，完成新建或改建桥梁交付使用后的首次全面检测数据电子化录入和查询。

**本模块实现的核心功能：**
- 初始检查记录的创建（20个基本信息字段 + 动态检测项列表）
- 检测项的灵活添加（22类检测项：桥面高程/拱轴线/材质强度/索力等）
- 初始检查记录列表查询
- 初始检查记录详情查看和报表打印

#### 2.3.2 模块输入数据

**用户输入数据 — 基本信息：**

| 字段 | 类型 | 是否必填 | 校验规则 | 来源表 |
|------|------|---------|---------|--------|
| inspect_id | 文本 | 是 | 最长20字符，建议格式"INI-YYYY-NNN" | — |
| bridge_id | 下拉选择 | 是 | 必须在bridge表中存在 | bridge |
| across_name | 文本 | 否 | 被跨越道路名称 | — |
| bridge_length | 数字 | 否 | 最大值99999.99 | — |
| max_span | 数字 | 否 | 最大跨径 | — |
| struct_type | 文本 | 否 | 上、下部结构形式 | — |
| construct_method | 文本 | 否 | 施工方法 | — |
| completion_date | 日期 | 否 | 不晚于检查日期 | — |
| inspect_date | 日期 | 是 | 合法日期 | — |
| climate | 文本 | 否 | 检查时气候 | — |
| temperature | 数字 | 否 | -50.0至60.0℃ | — |
| recorder | 文本 | 否 | 记录人 | — |

### 2.4 M04 — 定期检查记录管理模块

#### 2.4.1 模块功能描述

本模块基于《JTG 5120-2021》附录C（C-1至C-6），按6种桥型分别管理周期性检查数据。支持部件评分（0-5级制）、缺损记录（类型/位置/范围/照片）、养护建议和技术状况等级评定。

**本模块实现的核心功能：**

### 2.6 M06 — 系统管理模块

#### 2.6.1 模块功能描述

本模块完成系统的基础配置和管理维护功能，确保系统安全、稳定运行。

**本模块实现的核心功能：**
- 用户登录/登出认证
- 角色权限配置
- 用户管理（增删改查）
- 基础字典维护

#### 2.6.2 模块输入数据

| 功能 | 输入字段 | 校验规则 |
|------|---------|---------|
| 用户登录 | username, password | username存在且密码匹配 |
| 用户新增 | username, password, real_name, role | username唯一，password最小6字符，role必须有效 |
| 用户修改 | real_name, role, phone, email, is_active | role必须有效 |
| 字典维护 | dict_type, code, name, sort_order | (dict_type, code)联合唯一 |

#### 2.6.3 模块输出数据

| 输出内容 | 表现形式 | 说明 |
|---------|---------|------|
| 登录结果 | 重定向到首页或错误提示 | 登录成功建立session |
| 用户列表 | HTML表格 | 用户管理界面 |
| 操作反馈 | Alert消息 | 成功/失败提示 |

#### 2.6.4 模块设计流程

```
开始
  │
  ├─[登录] GET/POST /auth/login
  │   ├─ GET → 显示登录表单
  │   └─ POST → 验证用户名密码
  │       ├─ 成功 → login_user() → redirect 首页
  │       └─ 失败 → flash错误消息 → 返回登录页
  │
  ├─[登出] GET /auth/logout
  │   └─ logout_user() → redirect 登录页
  │
  └─[认证守卫] 每个业务路由前
      └─ @login_required 装饰器检查 session
          ├─ 已登录 → 继续处理
          └─ 未登录 → redirect /auth/login
```
