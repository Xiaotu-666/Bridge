## 第三章 其它架构

### 3.1 逻辑架构

本系统采用 **三层架构（3-Tier Architecture）** 设计，各层职责分明、独立演化：

```
┌─────────────────────────────────────────────────┐
│              表现层 (Presentation Layer)          │
│   HTML5/CSS3/Bootstrap 5 / Jinja2模板引擎        │
│   负责用户界面展示、用户交互                      │
│   文件位置: src/templates/*.html, static/css/     │
├─────────────────────────────────────────────────┤
│            业务逻辑层 (Business Logic Layer)      │
│   Python Flask Blueprint 路由控制器               │
│   负责业务规则、数据校验、流程控制                │
│   文件位置: src/routes/*.py                       │
├─────────────────────────────────────────────────┤
│             数据访问层 (Data Access Layer)        │
│   SQLAlchemy ORM / Python模型类                   │
│   负责数据持久化、实体关系映射                    │
│   文件位置: src/models/__init__.py                │
├─────────────────────────────────────────────────┤
│              数据存储层 (Data Storage)            │
│   SQLite 3 数据库文件                             │
│   文件位置: database/bridge_inspection.db          │
└─────────────────────────────────────────────────┘
```

**设计原则：**
- 表现层不可直接访问数据存储层，必须通过业务逻辑层
- 业务逻辑层通过SQLAlchemy ORM间接操作数据库，不直接写SQL
- 各层通过接口契约通信，可独立测试和替换

### 3.2 物理架构

本系统采用 **B/S（Browser/Server）** 物理架构，单服务器部署。

```
┌─────────┐     HTTP/HTTPS      ┌────────────────┐
│  浏览器   │ ◄──────────────────▶ │  Flask Web Server │
│ (客户端)  │                      │  Python 3.8+     │
└─────────┘                      │  :5000 端口      │
                                   │                  │
                                   │  ┌────────────┐ │
                                   │  │ SQLite DB   │ │
                                   │  │ (单文件)    │ │
                                   │  └────────────┘ │
                                   └────────────────┘
```

| 组件 | 角色 | 说明 |
|------|------|------|
| 客户端浏览器 | 用户界面 | 支持Chrome/Firefox/Edge等现代浏览器 |
| Flask Web Server | 应用服务器 | 处理HTTP请求，执行业务逻辑，渲染模板 |
| SQLite数据库 | 数据持久化 | 单一文件存储全部业务数据 |

### 3.3 运行架构

系统启动流程：

```
1. run.py 启动
   │
   ├─ create_app() → Flask应用工厂
   │   ├─ 加载config.py配置
   │   ├─ 初始化SQLAlchemy ORM
   │   ├─ 初始化Flask-Login认证模块
   │   └─ 注册4个Blueprint路由模块
   │
   ├─ db.create_all() → 首次自动建表
   │
   └─ app.run(host='0.0.0.0', port=5000, debug=True)
       └─ 监听HTTP请求循环
```

请求处理流程：

```
HTTP请求 → Flask路由匹配 → @login_required校验
  → Blueprint视图函数 → 数据验证 → 业务处理
    → SQLAlchemy ORM操作 → SQLite SQL执行 → 结果返回
      → Jinja2模板渲染 → HTML响应 → 浏览器展示
```

### 3.4 开发架构

项目采用 **MVC（Model-View-Controller）变体** 组织源码：

| 层次 | MVC对应 | 文件目录 | 职责 |
|------|---------|---------|------|
| Model | Model | src/models/ | 数据实体类、关系映射 |
| View | View | src/templates/ + src/static/ | 界面模板、样式 |
| Controller | Controller | src/routes/ | 请求处理、业务调度 |

### 4.2 数据库平台选择

| 对比项 | SQLite（已选） | MySQL | PostgreSQL |
|--------|:---:|:---:|:---:|
| 部署复杂度 | ★ 极简（零配置） | ★★★ 需安装服务 | ★★★ 需安装服务 |
| 适用规模 | 小型项目（< 10万条） | 中型（百万-千万） | 大型（千万-亿） |
| 并发支持 | 有限（串行写） | 良好 | 优秀 |
| GIS支持 | 无 | 有（MySQL 8+） | 有（PostGIS） |
| 迁移成本 | — | 修改1行配置 | 修改1行配置 |
| **选择结论** | 当前阶段最优 | 可扩展方案 | 可扩展方案 |

> **选择理由**：课程设计阶段，数据量小、单用户操作，SQLite零配置部署最适合；通过SQLAlchemy抽象，未来仅需修改`config.py`中一行`DATABASE_URL`即可切换至MySQL/PostgreSQL。
