# 数据库中文命名说明

## 1. 命名方案

系统采用“英文物理表 + 中文数据库视图”的双命名方案：

- `tb_*` 表是后端、Flyway 与外键约束使用的物理表，保持英文编码，避免破坏既有程序。
- 每张物理表增加中文表注释，例如 `tb_bridge` 的注释为“桥梁（物理表：tb_bridge）”。
- 每张物理表建立中文视图，例如 `桥梁`、`桥梁类型`、`部位`、`部件`。
- 中文视图中的所有属性均使用中文名称，例如 `桥梁编号`、`路线编号`、`桥梁类型编码`、`桥梁名称`。

该方式同时满足程序稳定性、数据库可读性和 PowerDesigner 展示要求。后端继续访问物理表，设计与查询人员使用中文视图。

## 2. 查询示例

```sql
SELECT `桥梁编号`, `路线编号`, `桥梁类型编码`, `桥梁名称`, `管养单位`
FROM `桥梁`;

SELECT `桥梁类型编码`, `部位编码`, `部件编码`, `显示序号`
FROM `桥型部件配置`
ORDER BY `桥梁类型编码`, `显示序号`;

SELECT `桥梁编号`, `部位编码`, `部件编码`, `部件序号`, `所在位置`
FROM `桥梁具体部件`;
```

## 3. PowerDesigner 命名

- Entity/Table Name：中文业务名称，如“桥梁具体部件”。
- Entity/Table Code：英文物理表名，如 `tb_bridge_specific_component`。
- Attribute/Column Name：中文属性名，如“桥梁部件编号”。
- Attribute/Column Code：英文物理字段名，如 `bridge_component_id`。

这样 CDM/PDM 图以中文展示，生成 SQL 时仍使用稳定的英文 Code。

## 4. 重点关系

- `部位` 1:N `部件`：每个标准部件只归属一个部位。
- `部件` 1:N `桥梁类型部件配置`，`桥梁类型` 1:N `桥梁类型部件配置`：配置只负责关联桥型与标准部件，不重复关联部位。
- `桥梁类型` 0:N `桥梁`：每座桥梁必须属于一个桥梁类型，桥梁类型可以暂未被采用。
- `桥梁类型部件配置` 0:N `桥梁部件`，`桥梁` 1:N `桥梁部件`：桥梁部件是模板配置在具体桥梁上的实例化分组。
- `桥梁部件` 1:N `桥梁具体部件`：实际桥墩、支座、主梁等实例归入对应桥梁部件。
- `桥梁` 1:N `桥梁基本信息`：基本信息按版本保留历史，每座桥梁仅一条当前有效版本。
- `桥梁具体部件` 1:N `桥梁具体部件检查记录`：检查记录必须明确对应一个实际部件。

数据库迁移文件为 `backend/src/main/resources/db/v2/V9__chinese_database_views.sql`。
